Zero-Trust End-to-End Architectural Flow

[Client Browser] ➔ [Spring Security 6: FormLogin / BCrypt / CSRF / SessionFixation] ↓ [Controllers: Auth / Dashboard / Document / Audit] ↓ [DocumentService: IDOR Defense, Role Ownership Checks, File Whitelisting] ↓ ├── [StorageService: Randomized UUID Obfuscation, Path Traversal (.normalize()) Sanity] ├── [PermissionService: Granular READ/EDIT Grants, Immediate Request Revocation] └── [AuditService: SHA-256 Chained Hash Ledger, Autonomous REQUIRES_NEW Persistence] ↓ [Persistence: In-Memory H2 (Dev) / MySQL 8.x (Prod)]
🔐 Autonomous Security Denials

Uses @Transactional(propagation = Propagation.REQUIRES_NEW) so that when IDOR violation throws a SecurityException, the security denial is committed immutably without rolling back with the business logic.

📁 Private Obfuscated Storage

Files stored outside the web root as {uuid}.ext. Original filenames preserved in metadata only. Strict file path normalization prevents directory traversal attacks.

Blockchain-Style Cryptographic Hash Ledger

Every audit event calculates a deterministic SHA-256 digest using its canonical payload concatenated with the preceding block's hash:

CurrentHash = SHA-256( Index || Timestamp || Actor || Action || ResourceId || Status || Details || PreviousHash )
  • Genesis Block: Seeded with an immutable root hash of 64 zero-characters (00000000...).
  • Deterministic Timestamp Serialization: Timestamps are truncated to the second (ChronoUnit.SECONDS) to guarantee byte-for-byte SHA-256 reproducibility across different database drivers.
  • Real-Time Breach Alert: The Admin can click "Simulate DB Tampering" on the Audit page to watch the verification engine detect altered records instantly in real time.
