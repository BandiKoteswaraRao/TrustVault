Zero-Trust End-to-End Architectural Flow

[Client Browser] ➔ [Spring Security 6: FormLogin / BCrypt / CSRF / SessionFixation] ↓ [Controllers: Auth / Dashboard / Document / Audit / Profile / AdminUser] ↓ [Service Layer: DocumentService, PermissionService, UserService, AuditService] ↓ [Dual Storage Adapter: Supabase Private Storage / Fallback Local Storage] ↓ [Database: Supabase PostgreSQL / Embedded H2 Mode / MySQL] ↓ [Tamper-Evident SHA-256 Hash Chain with Autonomous REQUIRES_NEW Logging]
S - Spoofing Identity

Mitigated by Spring Security 6 session management, BCrypt cost 12 password hashing, and server-side authentication checks on every request.

T - Tampering with Data

Mitigated by SHA-256 cryptographic hash chaining for all audit records and raw content SHA-256 hashing for documents.

R - Repudiation

Autonomous transaction logging (Propagation.REQUIRES_NEW) records all actions, actors, IP addresses, and outcomes irrevocably.

I - Information Disclosure (IDOR)

Eliminated by PermissionService.canRead() & canEdit() verifying ownership or explicit grants before returning any metadata or file bytes.

D - Denial of Service

Enforced 10MB multipart file size caps, connection pooling (HikariCP), and maximum concurrent session restrictions.

E - Elevation of Privilege

Server-side role demotion on registration, method-level @PreAuthorize, and immutability checks prevent self-assigned admin privileges.

Every security event creates a cryptographically sealed block where:

current_hash = SHA256(previous_hash + timestamp + actor + action + target + status + ip)

If any row in the database is modified or deleted, the hash chain breaks from that point forward and is immediately flagged by the verification engine.
